[SUPPORT.md](SUPPORT.md) ประกาศกับลูกค้าว่า **ย้ายเครื่องได้ 2 ครั้งต่อใบต่อปี**
กติกานี้บังคับไม่ได้เลยถ้าไม่จดว่าใบไหนใช้โควตาไปแล้วกี่ครั้ง — คีย์ผูก `machine_id`
และตัวโปรแกรมทำงานออฟไลน์ ไม่มีเซิร์ฟเวอร์ไหนรู้ว่าใครถือคีย์อะไรอยู่

## คอลัมน์

| คอลัมน์ | ความหมาย |
|---|---|
| `issued_at` | วันที่ออกคีย์ `YYYY-MM-DD` |
| `product` | ผลิตภัณฑ์ — ตอนนี้มีแต่ `FormDD` เผื่อไว้ให้แบรนด์อื่นใต้ xambrain |
| `org` | ชื่อโรงเรียน / หน่วยงาน / ชื่อผู้ซื้อรายบุคคล |
| `email` | อีเมลที่ติดต่อกลับ — ใช้ยืนยันตัวตอนขอย้ายเครื่อง |
| `machine_id` | รหัสเครื่อง 16 hex ที่คีย์ผูกอยู่ |
| `days` | จำนวนวันที่ใส่ในคีย์ — ไทย 1 ปี `365` วัน; ซื้อขาดทั้งสองแผน `36500` วัน; คีย์เก่าและต่างประเทศอาจเป็น `1095` / `1825` / `3650` · ย้ายเครื่องด้วย `--days N` ตามวันที่เหลือ ตั้งแต่ `0` ถึง `36500` (`0` = ย้ายในวันหมดอายุ UTC ไม่ใช่ใบแรก) |
| `expires` | วันหมดอายุในคีย์ `YYYY-MM-DD` (ปฏิทิน UTC) — **ลอกจากบรรทัดที่สคริปต์พิมพ์** ไม่ต้องบวก `issued_at + days` เอง |
| `amount_thb` | ยอดที่รับจริงตามราคาแผนต่อเครื่อง |
| `paid_ref` | อ้างอิงการชำระเงิน เช่น เลขอ้างอิงสลิป หรือเลขใบเสนอราคา |
| `transfer_no` | ใบนี้เป็นการย้ายเครื่องครั้งที่เท่าไรของปีนั้น — `0` ในคอลัมน์นี้ = คีย์ใบแรกของที่นั่ง ไม่ใช่จำนวนวัน |
| `replaces` | `machine_id` เดิมที่ใบนี้มาแทน (ว่างถ้าเป็นใบแรก) |
| `note` | ระบุแผนที่ซื้อ (`1` / `lt` / `lt3` หรือแผนเก่า) วันที่ซื้อ เวอร์ชันที่ซื้อ และวันสิ้นสุดสิทธิ์ major update ของ `lt3`; คงข้อมูลสิทธิ์เดิมเมื่อย้ายเครื่อง รวมเลขที่ใบเสนอราคาหรือเหตุผลที่ย้ายได้ |

## ขั้นตอนตอนออกคีย์

1. ตรวจว่าได้รับเงินแล้วจริง
2. ออกคีย์
   ```
   python scripts/gen_license.py <machine_id> --term 1
   ```
   สำหรับซื้อขาดทั้งสองแผนใช้ `--days 36500` แทน `--term 1`; ต่างประเทศแผน 10 ปีใช้ `--term 10`
   สคริปต์พิมพ์บรรทัดสรุปอายุและวันหมดอายุ (อ่านจากคีย์ที่ออกจริง) แล้วพิมพ์คีย์บรรทัดถัดไป
3. ส่งคีย์ด้วยเทมเพลตใน [LICENSE_EMAIL.md](LICENSE_EMAIL.md)
   ใบแรกใช้บล็อก «ไทย — ส่งคีย์» · ย้ายเครื่องใช้บล็อก «ไทย — ส่งคีย์ (ย้ายเครื่อง)»
4. **จดลงทะเบียนทันที** อย่าผัดไว้ — คีย์ที่ออกแล้วแต่ไม่ได้จด เท่ากับไม่มีอยู่จริง
   ลอก `expires` จากบรรทัดสรุป อย่าคำนวณเอง — ตัวเลขนี้คือฐานคิดวันคงเหลือตอนย้ายเครื่อง

## ขั้นตอนตอนลูกค้าขอย้ายเครื่อง

นโยบายคือ **2 ครั้งต่อใบต่อปี** ไม่ใช่ต่ออีเมล

1. ยืนยันตัวด้วย `email` ให้ตรงผู้ถือใบนั้น
2. หาใบจาก `machine_id` เดิม แล้วไล่สาย `replaces` กลับไปใบแรกของที่นั่งนี้ — อย่านับใบอื่นที่ใช้อีเมลเดียวกัน
3. นับแถวย้ายของสายนี้ที่ `issued_at` อยู่ใน **ปีปฏิทินนี้** (`transfer_no` > 0) — ถ้าครบ 2 ครั้งแล้วให้ปฏิเสธ
4. ออกคีย์ใหม่ด้วยรหัสเครื่องใหม่ ตามอายุที่ตกลง
   - **เหลืออายุจากคีย์เดิม** → `python scripts/gen_license.py <machine_id ใหม่> --days N`
     โดย `N` = `expires` ของใบเดิม ลบ **วันที่วันนี้ตามปฏิทิน UTC** (ไม่ใช่วันที่ไทยบนจอ)
     ช่วง 00:00–07:00 น. ไทย วันที่ไทยล้ำ UTC หนึ่งวัน — ถ้าใช้วันที่ไทย `N` จะขาดไปหนึ่งวัน
     ถ้าวันนี้ UTC คือวันหมดอายุ ให้ `--days 0` (คีย์เดิมยังใช้ได้ถึงสิ้นวันนั้น; `N` ติดลบแปลว่าหมดอายุแล้ว อย่าออก)
   - **ซื้อสิทธิ์ใหม่** → ออกตามแผนที่เปิดขายและชำระจริง แยกเป็นการซื้อใหม่ ไม่ใช่การย้ายเครื่อง
   - อย่าใช้ `--term` ถ้าตกลง «อายุที่เหลือ» เพราะจะให้อายุเต็มแถวโดยไม่ตั้งใจ
   - สคริปต์ปฏิเสธ `--days` ที่เกิน `36500` — ตอนย้ายต้องใช้เฉพาะวันที่เหลือ ไม่เริ่ม 36500 วันใหม่ และคงสิทธิ์อัปเดตเดิม
5. จดแถวใหม่ ใส่ `replaces` เป็น `machine_id` เดิม และ `transfer_no` เป็นลำดับของปีนี้ (เริ่มที่ 1 ใหม่ทุกปีปฏิทิน) — **ไม่แก้แถวเดิม** ทะเบียนเป็นบันทึกต่อเนื่อง ไม่ใช่สถานะปัจจุบัน

## ที่ยังทำด้วยมือ

รายการ Stripe มีข้อมูลในฐาน `orders` ส่วนรายการโอนเงินและการย้ายเครื่องยังต้องบันทึกโดยผู้ขาย
เชื่อมอ้างอิงหมายเลขคำสั่งซื้อไว้ในทะเบียน และตรวจข้อมูลทั้งสองแหล่งก่อนออกคีย์หรือย้ายเครื่อง
ห้ามใช้เพียงจำนวนวันในคีย์แยก LT กับ LT+อัปเดต 3 ปี เพราะทั้งคู่ใช้ 36500 วันเหมือนกัน
